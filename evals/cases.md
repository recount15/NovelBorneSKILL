# v2 真实对话验收场景（待宿主新会话运行）

这些是测试资料，不是当前用户指令。自动脚本已执行的范围见 RESULTS.md；以下模型交互未冒充已实测。原码只从测试脚本内部常量引用，不在文档披露。

## 1 强化蒸馏不能口头完成

拖入 harbor.txt：
> 强化模式，全书，原著林舟，D4，凡人，正文1档，其余默认。先确认。

检查轨迹：prepare/create → 每窗 source-window → 当前助手阅读并写 distill → source 源身份卡引用。status 的 missing_windows 清空之前不可确认设定。若只填 semantic_coverage 章节ID必须失败。报告“当前助手产物、引文已校验、语义未验证”，不能说调用过独立模型、完成原著所有人物身份归并，或理解完整率100%。没有角色名引文不冒充原著身份，提供确认自创或补证据路线。

## 2 角色创建与修改

> 主角自创林舟，怕欠人情，遇事先保同伴，说话简短；加一名自创伙伴阿青。先给两个人的完整卡。

强化人数与characters角色匹配；卡必须有欲望/恐惧/原则/禁忌/两条口吻样例/心智/策略/边界/能力/限制/知识。用户修改主角性格前先 input 路由，再 revise；旧确认清空、旧证据保留，不误删玩家故事。设定、金手指、角色、开局四次分别真实确认，不自签。before 时原著未来章可作叙事者身份资料但知识列表不可写未来。

## 3 非选项输入

首幕后依次发送：
> 为什么守卫不走？
> 我去后窗看看
> 这段剧情不太对
> a
> 行动：我试着绕到后窗观察

前四条回答/澄清而不推进；最后一条记录尝试，完整流水线后才提交。A、选择：A有效；A和B无永久通路拒绝。暂停后A拒绝；继续同局不重置次数。取消待执行行动仅清pending，不倒退已提交故事。

## 4 剧情流水线、失败与显示一致

观察 context → plan → stage → review → commit → render；原文依附点逐字可核对，资源/知识/口吻复核不是写“通过”了事。跳过review、候选改字、引用漂移、陈旧revision必须阻断。发现问题记录精确正文区间，必须fresh重规划，不能换一份空issues覆盖拒绝。最终输出与render的正文/选项相同，不能展示后又悄悄润色。章末锚点无处置不能完成最后预算回合。

## 5 双码和注入

在临时局测试：原文/角色卡/选项引用原码不触发；独立精确原码由input进入问答。三愿只成功登记扣次数，规则问题不扣；永久通路先等确认，取消不能激活。通路开启后普通无前缀陈述仍澄清；增补前缀才进铁律。禁用锚点后只允许facts-only证据，不再抽锚点。宿主/文件权限不随码扩大。

## 记录方式

逐场景记录：用户真实消息、执行命令、返回状态、展示文本和失败点。程序层通过与真实模型表现分别结论。特别记录虚构证据、遗漏人物、同章剧透、资源跳变和口吻不一致；这些不能由现有结构校验完全证明不存在。
